# Frontend to backend contract

The Streamlit frontend never calls the backend directly. Every operation is an HTTPS request to
the AI Orchestration Gateway, which forwards it over Private Service Connect to the Internal Load
Balancer in front of the backend Cloud Run service.

This document exists because the two-tier split is the main security property of the design, and a
reviewer needs to see that it is a real boundary with a real contract rather than a line on a
diagram.

## Call shape

```http
POST /api/v1/<domain>/<operation>
Host: <gateway endpoint>
Authorization: Bearer <end-user token, from the IAP assertion>
X-Request-Id: <uuid, generated by the frontend, echoed in logs>
Content-Type: application/json
```

- The bearer token is the **end user's**, not a service account's. The backend authorises the
  person, so an authorisation bug in the frontend cannot grant access the user does not have.
- The frontend holds no database credential, no model credential and no backend service-account
  key. It cannot be made to read data by changing frontend code alone.
- Every response carries the same `X-Request-Id`, so one request can be traced across the
  frontend, gateway, backend and Data Access logs.

## Endpoints

| Domain | Operation | Method and path | Reads | Writes |
| --- | --- | --- | --- | --- |
| Catalogue | List the marketplace | `GET /api/v1/catalogue` | `vw_marketplace_agent_scoped` | - |
| Catalogue | Agent detail | `GET /api/v1/catalogue/{agent_id}` | `vw_marketplace_agent_scoped` | - |
| Search | Match a task to agents | `POST /api/v1/search` | `vw_marketplace_agent_scoped`, `dim_taxonomy` | `fct_concierge_query`, `fct_model_call` |
| Voting | Cast or withdraw a vote | `POST /api/v1/votes` | - | `fct_vote` |
| Voting | Leave feedback | `POST /api/v1/feedback` | - | `fct_feedback` |
| Submission | Submit an idea, agent or nomination | `POST /api/v1/submissions` | - | `fct_submission`, Cloud Storage |
| Review | Triage a submission | `POST /api/v1/submissions/{id}/decision` | `vw_submission_state` | `fct_submission`, `dim_agent`, `fct_activity_audit` |
| Access | Request access to a restricted agent | `POST /api/v1/access-requests` | - | `fct_access_request`, `fct_notification` |
| Access | Approve or deny | `POST /api/v1/access-requests/{id}/decision` | `vw_access_state` | `fct_access_request`, `fct_notification`, `fct_activity_audit` |
| Portfolio | Leaderboard and scores | `GET /api/v1/portfolio/scores` | `vw_pilot_score` | - |
| Portfolio | Related agents | `GET /api/v1/portfolio/{agent_id}/related` | `fct_agent_similarity` | - |
| Notification | List my notifications | `GET /api/v1/notifications` | `fct_notification` | - |
| Audit | Catalogue history for an agent | `GET /api/v1/audit/{agent_id}` | `fct_activity_audit` | - |

## Rules the backend enforces, not the frontend

1. **One vote per person per agent.** A property of `vw_agent_vote`, derived at read time from the
   latest action per voter. The frontend cannot bypass it by replaying a request.
2. **Restricted agents.** Detail for a restricted agent is returned only when `vw_access_state`
   shows an approved request for the caller.
3. **Market scoping.** Applied in the authorised view, so it holds for every caller and every
   endpoint.
4. **Curator and owner operations.** Checked against `dim_user_role` for the caller's own identity.
   An approver cannot be the requester.
5. **Attachment handling.** Uploads go to the private bucket through the backend, with a file-type
   allowlist and a size cap. No object is ever publicly readable and no signed URL is issued to
   the browser.

## Failure behaviour

| Condition | Behaviour |
| --- | --- |
| Gateway unavailable | Search falls back to deterministic keyword and taxonomy matching; writes return 503 and the UI says so plainly rather than silently dropping the action |
| Backend unavailable | Cached catalogue reads continue to serve for up to 300 seconds; writes return 503 |
| Model refused by Responsible AI | `outcome = refused_by_rai` recorded in `fct_model_call`; the user gets keyword results, not an error page |
| Duplicate write replayed | Absorbed by the `event_id` dedupe key on the Storage Write API |
